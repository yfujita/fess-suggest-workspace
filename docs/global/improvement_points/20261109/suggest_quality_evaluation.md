# サジェスト候補品質の実機評価（日本語重点）

fess のサジェスト API を実機で操作し、候補語の品質上の問題点を洗い出した結果をまとめる。コード読解ではなく、外部から観測できる振る舞いが対象。

## 1. 評価条件

| 環境 | エンドポイント | データ |
| --- | --- | --- |
| ローカル（最新） | `GET /api/v2/suggest-words?q=&num=15&fn=_default&fn=content&fn=title` | はてなブックマーク一覧ページ100件のクロール結果（ニュース・IT・暮らし） |
| デモ（やや古い） | `GET /api/v1/suggest-words?q=&num=15&field=_default&field=content&field=title` | fess/OpenSearch 等の技術文書（多言語）と BuzzFeed 系記事。候補に `labels`（`fess`/`buzzfeed`）が付く |

- クエリ: 1文字（ひらがな・カタカナ・漢字・英字）、単語、複数語、表記ゆれ、読み入力、ノイズ候補を、ローカル約200件・デモ約110件。
- 文書側の存在確認はローカルのみ可能（`/api/v2/search`）。デモの v1 には検索 API が無く、デモの0件は「データに無い」のか「処理で落ちた」のか区別できない。
- 0件は `record_count=0` の応答（デモでは `data` キー自体が無い）。
- データ規模・語彙が偏るため、頻度閾値に由来する欠落は本番規模では変わりうる。
- 凡例: **[確認]** 実機で観測 / **[推測]** 原因の推定（未検証）。優先度: 高=体験に直結、中=品質向上、低=あれば良い。

## 2. 良好な点

- 読み仮名入力が機能する。`にほん`→日本経済新聞/日本語、`とうきょう`→東京、`たかいち`→高市、`あまぞん`→アマゾン（ローカル）。
- カタカナ・半角カナ・全角英字が正規化される。`ニホン`/`ﾆﾎﾝ`/`にほん` が同結果、`ＡＩ`=`AI`（両環境）。
- 前方一致補完は自然。`東`→東京/東京大学、`日本経`→日本経済新聞。
- 助詞・助動詞は概ね抑制される。`する`→スルー、`です`→デスク（ローカル）。

## 3. 改善点一覧

「環境」は再現した環境（L=ローカル、D=デモ）。両方で再現するものは、データ起因ではなく生成・フィルタ処理の問題と考えられる [推測]。

| # | 優先度 | 環境 | 改善点 |
| --- | --- | --- | --- |
| 1 | 高 | L,D | 複数語（スペース区切り）入力で候補が出ない |
| 2 | 高 | L | 複合語・固有名詞が候補にならない |
| 3 | 高 | L,D | 活用語尾・語幹・記号の断片が候補になる |
| 4 | 高 | L,D | 同音異義語・読み前方一致のノイズ |
| 5 | 高 | D | 他言語（独・西・仏）の単語が混入する |
| 6 | 高 | D | 数値・タイムスタンプが候補になる（ローカルは逆に数字が0件） |
| 7 | 中 | L,D | 汎用語・1文字語が上位に出る（デモは中国語由来の漢字も混入） |
| 8 | 中 | L,D | URL断片・設定名・識別子・ゴミ文字列が候補になる |
| 9 | 中 | L,D | 長音の表記ゆれが統合されない |
| 10 | 中 | L,D | 英字入力に日本語の読み一致候補が混在し、並びが不安定 |
| 11 | 中 | L | 専門語（`fess`/`docker` 等）が候補に出ない |
| 12 | 低 | L,D | 並び順の根拠が弱い（意味の薄い語が先頭） |
| 13 | 低 | L | `fn`（フィールド）指定で結果が大きく変わる |
| 14 | 低 | L | 人名の断片（名字のみ）が候補になる |
| 15 | 低 | L,D | 候補が1件（入力語と同一語のみ）で終わり、救済・関連語提示が無い |
| 16 | 低 | D | 読み入力の補完幅が狭い（`しゃかい`・`たかいち` が0件。データ差の可能性あり） |

## 4. 項目詳細

### #1 複数語入力で候補が出ない（高）
- 観測 [確認]: `日本 経`、`日本 経済`、`AI 活`、`トランプ 関`、`検索 エンジン` がすべて0件。ローカルでは `日本 経済` が検索で98件ヒットする。デモも `日本 経` が0件。
- 原因 [推測]: 単語単位でのみ候補を生成し、複数語クエリの前方語に続く語（共起・組み合わせ）を扱っていない。#15 も同根。
- 補足: クエリベースのサジェストでは複数語が表示されることを確認。

### #2 複合語・固有名詞が候補にならない（高）
- 観測 [確認]: `新型コロナ`（100件ヒット）、`大統領選`（3件）、`高市早苗`、`石破首相`、`ワクチン接種` が候補0件。`円安` は4文書に出現するが候補0件で、`円` では `円`/`エントリー`/`演奏` のみ。`新型` は `新型` のみ、`コロナ` は `コロナ` のみ（断片は出るが連結語は出ない）。
- 原因 [推測]: 形態素分割後の単位が候補になるため、複合名詞は断片でしか残らない。または出現頻度の閾値で落ちる。

### #3 断片が候補になる（高）
- 観測 [確認]: `なかっ`、`よかっ`、`おもし`、`ハンバーガ`、`大き`、`難し`、`ッ`/`ッッ`（ローカル）、`ー`/`ーー`/`ーーーーー`/`ーッッ`（デモ）、`ne`、`ku`。
- 原因 [推測]: 品詞・文字種フィルタが不足。促音・長音のみ、活用語の途中形が通る。

### #4 同音異義語・読み前方一致のノイズ（高）
- 観測 [確認]: `地震`→自身/自信、`金利`→筋力/近隣、`コロ`→衣/衣替え（デモは殺し）、`ワク`→枠組み/枠、`石`→意識/医師/維新、`ため`→試し、`tokyo`→徒競走、`ハンバ`→販売。デモの `金利` は入力語自体が出ず近隣/筋力のみが返る。
- 原因 [推測]: 読み（ローマ字化含む）一致で別表記の語を引く。表記一致 > 読み一致の優先度付けが無い。

### #5 他言語の単語が混入する（高、デモ）
- 観測 [確認]: `ände`→ändern/änderung、`sig`→siguiente/sigue/signifie/sigv4、`com`→commute/comme/compte、`の`→nombre/non。日本語ユーザーには不要。
- 対処の方向: 言語判定、または言語別フィールドでの絞り込み。

### #6 数値・タイムスタンプ（高）
- 観測 [確認]: デモ `2`→2/20/200/2026…、`2025`→`20250101000000000`/`20250129100000`。ローカルは `2024`/`2025`/`11` が0件（`2025` は70文書ヒット）で、デモと挙動が逆。年号 `令和` は出る。
- 原因 [推測]: 数字トークンの扱いに一貫したルール（長さ・桁・形式による除外）が無い。

### #7 汎用語・1文字語（中）
- 観測 [確認]: `ない`、`なく`、`なし`、`もの`、`こと`→事/言葉、`中`、`日`、`月`、`次`、`他`、`件`、`県`。デモは `あ`→愛/行/安/明/改、`か`→和/会/模、`本`→本地/本身、`ます`→升、`これ`→是重と、1文字漢字・簡体字由来の語が多い。
- 対処の方向: 最小長・文字種の制限、汎用語リストの強化。

### #8 ゴミ文字列・識別子（中）
- 観測 [確認]: ローカルは `wwwww`/`wwwwwww`、`https`、`com`、`jp`、`html`、`tokyofukubukuro`、`japanstatsmaps`、`ワロタ`。デモは `fess_config.bulk`、`fess.yyyymmddhhmmsssss`、`http.proxy.host`、`docker.network.inbound.bytes`、`github.com:codelibs`、`kubernetesclusterid`。
- 原因 [推測]: 英字の連続・URL部品・ドット/アンダースコア連結トークンの除外ルールが不足。トークン分割が粗い。

### #9 長音の表記ゆれ（中）
- 観測 [確認]: ローカルは `ハンバーガー` が0件で `ハンバーガ` のみ存在。両環境で `ユーザ`/`ユーザー`、`サーバ`/`サーバー`、`コンピュータ`/`コンピューター` が別候補として並立。デモは `ハンバーガー` が存在する。
- 原因 [推測]: 表記ゆれ統合が候補・表示の両方で未実施。解析時に長音が欠落する場合がある。

### #10 英字入力への日本語混在・並びの不安定（中）
- 観測 [確認]: ローカル `ai`→aizuk/airbnb/…/アイドル/相手/愛知、`ch`→中国/地域/調査。デモ `AI`/`ai`→愛/アイテム/相性（`ai` 自体の候補は無い）、`の`→note/nombre/non、`日`→日本…の後に history/high/hinzu、`し`→渋谷/使用/si/size。
- 原因 [推測]: ローマ字読み一致が日本語語彙全体に及び、日本語の読み一致と英字前方一致がスコア順で混在する。

### #11 専門語が出ない（中、ローカル）
- 観測 [確認]: `fess`/`elasticsearch`/`opensearch`/`docker` が0件（検索では `docker` 7件、`fess` 14件）。
- 原因 [推測]: 低頻度による除外。小規模データに由来する可能性が高い。

### #12〜#16（低）
- #12 順位: `あ`→あと/ai/アニメ、`に`→人気/日本/ニュース。意味の薄い語が先頭。出現頻度中心で、固有名詞・名詞句への重みが無い [推測]。
- #13 フィールド: ローカルで `に` が `fn=_default` のみだと0件、`content` は149件、`title` は2件。`fn` 省略時も少ない（`日本` 11件）。`_default` に候補が蓄積されていない設定の可能性 [推測]。
- #14 人名断片: `大槻`、`舎人`、`古謝`、`牟田`、`宮前`、`本田` など名字のみ [確認]。固有名詞の頻度・品詞による制御が未設定 [推測]。
- #15 救済無し: `日本経済` は2件、`ワクチン` は1件など、入力語のみで終わる [確認]。#1 と同根。
- #16 読みの幅: デモで `にほん`→日本語のみ、`たかいち`/`しゃかい`/`あまぞん` は0件（`しゃ` では社会が出る）[確認]。データ差の可能性があり断定できない。

## 5. まとめ

- 読み補完は有効だが、候補の生成単位が単語の断片に偏る点（#2, #3, #9）と、複数語入力への非対応（#1）が体験上の最大課題。
- ノイズ（#3, #4, #5, #7, #8, #14）は、品詞・文字種・頻度・言語・一致種別によるフィルタとスコア調整の組み合わせで改善できる見込み。
- 数字の扱い（#6）は環境で逆の挙動になっており、方針の明確化が必要。
- 原因はすべて [推測]。解析器設定と候補生成・フィルタ処理の実装調査で確認する必要がある。
- デモはローカルより古い版で、環境差の一部（`ッ` の有無、`ハンバーガー` の有無など）は版差・データ差の可能性が残る。
