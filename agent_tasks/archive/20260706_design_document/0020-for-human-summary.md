# 0020 設計書の人間向け簡易版の作成

> 対象: fess-suggest 改善設計書群（`docs/0000`〜`0004`） ／ 実施日: 2026-08-22
> 凡例: `docs/0000-design-overview.md` §3.1 に同じ

## 1. 依頼内容

「タスク `20260706_design_document` で作成した設計書について、**人間でも読めて内容をざっくり掴めるような簡易版**を作成する。`for_human` ディレクトリを作ってそこに入れる」

## 2. 成果物

| --- | --- | --- |
| `README.md` | 3 分サマリ ／ 変更点の一覧表 ／ 元の設計書の地図 | 全体 |

## 3. 方針と判断

| # | 判断 | 理由 |
| --- | --- | --- |
| 1 | **元の設計書は一切変更しない** | 依頼は「簡易版の作成」であり、設計内容の改訂ではない。第 8 版の閉包リファクタリング（`0019`）で整えた状態を壊さない |
| 2 | **`docs/for_human/` に置く**（`docs/` と同階層の子ディレクトリ） | 設計書セットと一緒に移設できる。相対リンク `01-...md` は同ディレクトリ内で閉じており、セットごと移動してもリンクが切れない |
| 3 | **番号（D / DM / MO / C / P / F）を本文からほぼ全廃した** | 「ざっくり掴む」ことが目的であり、番号は原典を引くための装置である。ただし **K 番号・G 番号・S/R 番号・R-1〜R-4 は残した** — これらは運用者が実際に会話で使う識別子だからである |
| 4 | **`file_path:line` を書かない** | 根拠に当たる必要が生じたら元の設計書を読むのが正しい。簡易版に根拠を転記すると、原典と二重管理になり陳腐化する（`0000` §3.3 の記述ルールと同型の判断） |
| 5 | **冒頭に「正確さより掴みやすさを優先」「判断には元の設計書を使う」と明記した** | 簡易版が原典として使われることを防ぐ。設計書セットの「正」の所在（`0001` = 公開契約、`0002` = データの形、`0003` = 手順）は README の地図で示した |
| 6 | **数値・固有名は元文書と一致させた** | 掴みやすさのために丸めてよいのは説明の粒度であって、事実ではない。公開 4 IF のメソッド数（2 / 12 / 7 / 9 = 30）、旧公開メンバ 48、fess 側 5 ファイル、ID 43 文字、語数上限 10 / 上限 50、G1 の既定 50% はいずれも原典どおり |

## 4. 簡易版で特に強調した 3 点

**元の設計書が「読めば分かる」形で持っているが、通読しないと掴めない要点を前に出した。**

| # | 要点 | 元の所在 |
| --- | --- | --- |
| 1 | **全面書き直しではない。** 重大度「高」の課題は 0 件で、アーキテクチャは健全。作り直すのは公開面・データの形・入れ替え手順の 3 つだけ | `improvement-proposal.md` §2.1 の全体評価 |
| 2 | **二重エイリアス機構は壊れていない。壊れているのは呼び出し側の制御フロー** | `0003` §1.1（同書が「中核は §1 である」と自ら述べている） |
| 3 | **ID 方式の変更により新旧共存は成立しない。** 全件再投入 → 検証 → 切替の一本道しかない | `0002` DM-15 / `0003` MO-6 |

## 5. 未実施・スコープ外

- **元の設計書への追記（簡易版への相互リンク）は行っていない。** `0000` の役割定義（索引であり設計内容を持たない）と `0019` で確立した参照規律に影響するため、必要であれば別作業とする。
- **図（アーキテクチャ図・状態遷移図）は作成していない。** `improvement-proposal.md` §1.3 の ASCII 図が既にあり、簡易版では S0〜S5 の流れ図のみテキストで持たせた。
- **英語版は作成していない。**
