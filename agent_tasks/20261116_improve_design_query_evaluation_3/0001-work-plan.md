## 2. 確定事項・前提

### 観測事象(評価書 §4 #3)
- 活用語の途中形: `なかっ`、`よかっ`、`おもし`、`大き`、`難し`
- 長音で終わる語の欠落: `ハンバーガ`(ローカルは `ハンバーガー` が 0 件で `ハンバーガ` のみ。#9 と同根の可能性)
- 促音・長音のみ: `ッ`/`ッッ`(ローカル)、`ー`/`ーー`/`ーーーーー`/`ーッッ`(デモ)
- ローマ字断片: `ne`、`ku`

### 原因の仮説(評価書では推測扱い。フェーズ1で検証する)
- H1: 文書経路のアナライザ(`contents_analyzer_ja`)の `pos_filter` が、形容詞・動詞の活用形(連用形・語幹など)を落とさない。
- H2: 語を表層形のまま候補にしており、基本形に戻していない。そのため活用の途中形が別語として残る。
- H3: 促音・長音・記号だけのトークンを除外する文字種フィルタが無い(最小長・文字種の制約が無い)。
- H4: `kuromoji_stemmer` 等により、長音で終わるカタカナ語の末尾の `ー` が落ち、`ハンバーガ` のような欠けた語が生まれる。
- H5: ローマ字断片(`ne`、`ku`)は、読み(ローマ字化)の前方一致経路、または英字トークンの断片分割から来る。
- H6: 候補は文書経路だけでなく、検索ログ経路や #2 で追加された連結語の経路からも出る(経路ごとに原因が異なる可能性)。

### 前提
- 評価環境は L(ローカル)。OpenSearch は `localhost:9200`、Fess は `localhost:8080` で稼働中のものを実測に使う。実測は読み取りのみ(`_analyze`、サジェスト API、suggest インデックスの検索)とし、インデックスの再作成・削除はしない。
- コードは `modules/fess-suggest` の `main` ブランチ(PR #107 の連結語対応を含む)を基準にする。ローカル Fess が組み込んでいる jar がこれと同じ版かは、フェーズ1で確認する。
- 他の改善点との関係(#2 連結語、#7 汎用語・1 文字語、#8 ゴミ文字列、#9 長音の表記ゆれ、#14 人名断片)は、同根または相互影響がある範囲で注記する。設計対象は #3 の断片に限る。#9 は `ハンバーガ` が #3 の観測にも含まれるため、重なる部分の切り分けを設計書に書く。
- 設計書に経緯(回答日・作業履歴への参照)は書かず、完結させる。
