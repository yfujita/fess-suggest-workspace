# 0009 外部レビュー指摘(R-01〜R-07)への対応

設計書 `task_docs/design_compound_word_suggest.md` に対する外部レビュー(7 件)を確認し、すべて妥当と判断して反映した(2026-11-13、221 → 263 行)。0004 の確定事項(A2、上限 5 トークン / 20 文字、品詞、案 B の扱い)は変えていない。

## 事実確認
- **R-01**: ローカルの `opensearch-3.9.0.jar`(`AnalyzeAction$CharFilteredText`)と `fesen-httpclient-3.9.0.jar`(`HttpAnalyzeAction$Fields`)を `javap -constants` で確認。キー定数はいずれも `"filtered_text"`(単数)。0008 で書いた `filtered_texts` は誤り。実装すると本文が取れず全チャンクが縮退する(0008 の「模擬の explain 応答で確認」はクライアント側のキーを確認していなかった)。
- **R-04**: `fess-res:fess_config.properties:1619-1623` で `limit.num.percentage=50%`、`limit.num=10000`、`limit.doc.size=50000`、`SuggestHelper.java:371-373` で `ESSourceReader` に設定されることを確認。
- `deleteDocumentWords`(`DeletionOperations.java:130-136`)は、文書由来のみの項目を削除し、検索ログ/ユーザー由来も持つ項目は `docFreq` を 0 に戻す。ロールバック手順はこの挙動に合わせて記載。

## 対応(設計書)
| ID | 対応 |
| --- | --- |
| R-01 | §3.1・§3.2・§5.2・§7 の `filtered_texts` を `filtered_text`(単数、値は配列の先頭要素)に修正。根拠と、誤ると全件縮退する旨を §3.1 に記載。§5.2 の統合テストを必須とし、実応答から例語の連結語が実際に生成されること(0 件縮退でないこと)を合格条件にした |
| R-02 | §3.2 に取りこぼし(超過列・中間末尾の部分語)を意図的な制約として明記。新設 §4.4 に整理し、部分列生成は比較検討用の案で確定変更ではないと明記。§5.1 に `新型コロナウイルス`・超過列の期待値(比較基準)を追加 |
| R-03 | 新設「本番有効化ゲート」(§7)で、応答サイズ・チャンク処理時間・ジョブ総時間・成功/縮退件数の測定を規定(50,000 文字級の長文、空白なし/あり、全角英数、半角カナ)。§3.4 の `enabled` 既定値を「暫定 `true`」とし、本番既定はゲート結果で確定。閾値はベースライン測定後に決める |
| R-04 | §3.5 に「インデックス定義の再作成は不要」と「既存文書への全件反映は自動では及ばない」を区別して記載。§4.2 に反映(通常/全件)・停止・ロールバック手順を追加。`enabled=false` にしても生成済み候補は即時消えない旨を明記 |
| R-05 | §4.3 に評価指標(例語取得率、代表プレフィックス上位候補とノイズ率、候補総数、更新時間)を追加。ゲートに組み込み |
| R-06 | §3.2 で `contains` は必要条件であり十分条件でないことを強調。offset(元の本文の座標)を `filtered_text` に直接適用しないことを明記。§5.1 に限界を確認するテストを追加 |
| R-07 | 新設 §4.5 で縮退件数と原因別内訳の観測を規定(ログ/カウンタの保持方法は実装時に決定)。§4.1 から参照、§5.1 にテスト追加、異常(連結語が 0 件に近い)の扱いをゲートに含めた |

## 判断
- R-02 の部分列生成方式は採用しない(初版は 0004 の確定どおり最大連続列のみ)。レビュー自身も提案扱いのため、制約の明記と比較用テストにとどめた。
- 「評価なしに本番既定 `true` を確定しない」は受け入れたが、実装の既定値は暫定 `true` のまま(開発・評価で効果を見るため)。リリース時の既定を決める条件をゲートにした。
- 数値の閾値は置かない(ベースライン未測定のため)。
