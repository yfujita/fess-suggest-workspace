# 0008 設計書への追加: 連結語が本文に存在することの保証

ユーザーから「品詞で結合すると、アナライザの挙動によって本文に存在しない単語を生成しないか。本文に確実に存在すると確認できるか」との懸念があり、設計書に反映した(2026-11-13)。0004 の確定事項(A2、上限、品詞、案 B の扱い等)は変えていない。

## 検証(オフライン再現。scratchpad の `chk/Chk.java`)
Lucene Kuromoji 9.5.0 に `MappingCharFilter`(`mapping_char` の簡易版。半角カナ・全角英数のみ)を前置して確認した。
- 品詞は「どの連続区間を連結するか」を決めるだけで、連結語は offset が連続するトークンの表層を並べたものになる。char_filter 適用後の本文の部分文字列で、現状の断片と同じ性質。
- offset は文字フィルタで文字数が変わっても元の本文の座標に戻って出力される(`ﾊﾞｲｵ` → term `バイｵ`、offset `[0,4)`)。隣接判定は元の本文の座標で成り立つ。
- 空白は `記号-空白` の別トークンになり、連結が途切れる。
- 連結語は原文そのままではなく正規化後の表層になる(`ＡＩ` → `AI`)。

## 設計書の変更(`task_docs/design_compound_word_suggest.md`、200 → 221 行)
- §3.2: 擬似コードに offset の妥当性検証(`0 <= start < end`、前のトークンと重ならない)と、連結した表層が char_filter 適用後の本文の部分文字列であることの照合を追加。「連結語が本文に存在することの保証」の節を追加(offset 欠落・重なりトークンによる誤連結の防止、照合が必要条件であることを明記)。
- §3.1: `analyzeTokenizerStage` の戻りを、トークンと char_filter 適用後の本文を持つ値(`TokenizerStageResult`)に変更。本文は `detail.charfilters[].filtered_texts` から読む。
- §4.1: offset 不正・照合不一致・本文が取れない場合は連結語を作らない(縮退)。
- §5.1 / §5.2: offset 不正、本文との照合、正規化(全角英数・半角カナ)のテストケースを追加。統合テストで「出力した連結語はすべて char_filter 適用後の本文の部分文字列」を検証。
- §7 確認事項 1: 本物の `mapping_char`(142 件)で文字数が変わる入力でも offset が元の座標で返ること、`filtered_texts` が返ること、評価データで照合不一致が 0 件であることを追加。

## 判断
- 本文が取れない場合は連結しない(存在を確認できない語は作らない方針を優先)。実環境で `filtered_texts` が返らなければ機能が働かないため、7 章 1(b) で実装前に確認する。
- 照合は必要条件(別の位置の一致を排除できない)。連続性の判定は offset の隣接が担う。
