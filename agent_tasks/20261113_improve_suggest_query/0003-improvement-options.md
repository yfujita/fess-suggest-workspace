# 0003 改善案の比較(フェーズ2)

担当: tech-advisor。リポジトリ内のコード・ファイルは変更していない。承認結果は末尾の「承認結果」に追記する(承認後は新規作業記録で残す)。

## 1. 推奨

**案 A2: Java 側(`parseDocument`)で、`_analyze` の explain から得た品詞・offset をもとに隣接名詞を連結し、連結語を追加で候補化する。断片(現状の候補)は残す。**

- 例語 6 語をすべて救済できる(Lucene Kuromoji 9.5.0 / IPADIC のオフライン再現)。
- `suggest_analyzer.json` を変更しないので、Y-09(既存環境ではアナライザ定義が更新されない)の影響を受けない。jar とアプリの更新だけで効く。
- `_vanilla` 構成でも動く見込み。連結対象の品詞・長さ上限・on/off を Java 側で制御できる。
- 案 B(ユーザー辞書)は A2 の補完として別課題に切り出す。補助案(`名詞-接尾-一般` を stoptags から外す)は不採用。

## 3. 例語での実測(連結対象品詞 11 種)

連結対象: `名詞-一般`、`名詞-サ変接続`、`名詞-固有名詞-一般`/`人名-一般`/`人名-姓`/`人名-名`/`組織`/`地域-一般`/`地域-国`、`名詞-接尾-一般`、`名詞-接尾-サ変接続`。offset が連続する対象品詞トークンの最大連続列を連結する。

| 入力 | 連結語 | 読み(トークンの reading を連結) |
| --- | --- | --- |
| 新型コロナ | 新型コロナ | シンガタ+コロナ |
| 大統領選 | 大統領選(`選`=名詞-接尾-一般) | ダイトウリョウ+セン |
| 高市早苗 | 高市早苗 | タカイチ+サナエ |
| 石破首相 | 石破首相 | イシバ+シュショウ |
| ワクチン接種 | ワクチン接種 | ワクチン+セッシュ |
| 円安 | 円安(`安`=名詞-接尾-一般) | エン+ヤス |
| 新型コロナウイルス感染症 | 5 トークンを 1 語に連結 | - |

- 空白・句読点・助詞・動詞で連結が途切れる(`検索 エンジン` は連結されない)。数詞・助数詞は対象外(`3000万円` や `令和5年度` は連結されず、#6 を悪化させない)。
- 良い例: `全国大会優勝者`、`機械学習モデル`、`東京都知事選挙`、`日経平均株価`。
- 弊害の例: ナビゲーション文字列 `ホーム製品情報会社概要` が 5 トークンの連結語になる。**長さ上限では防げない**(`新型コロナウイルス感染症` も 5 トークン)。ランキング(docFreq)に任せ、後続課題とする。

## 4. A2 の技術的根拠
- `_analyze` に `explain: true` を付けると、tokenizer 段の各トークンに `partOfSpeech` と `reading` の attribute が付く(Lucene の attribute 実装のキー名を javap で確認)。Fesen の HTTP クライアントは `detail` を読み、未知フィールドは `AnalyzeToken` の `attributes` マップに入る。custom analyzer のときだけ段別の結果が返るが、`contents_*_analyzer` は custom。
- 欠点: Lucene の explain 形式は experimental。段数分(約 7 段)のトークンが返り、応答が現在の数倍になる。実環境でのコスト測定が必要(未実施)。

## 5. #3 / #14 との相互影響
- A2 は断片を残して連結語を足すだけなので、現状の #3 / #14 を悪化させない(ただし項目数は増える)。
- 姓+名の連結語(`高市早苗`)が出れば、#14 の対策(姓だけの断片を落とす)を後続で安全に入れられる。
- #7(汎用語)の傾向は連結語の増加で変わりうる。#3 / #14 の改善は別途設計する。

## 6. 設計上の論点と推奨

| # | 論点 | 推奨 |
| --- | --- | --- |
| 1 | 連結語と断片の両方を候補にするか | 両方。`コロナ` など末尾側の語は連結語の前方一致で引けないため。断片の整理は #3 / #14 側 |
| 2 | 連結の単位 | 最大連続列のみ(2 トークン以上)。部分列は出さない |
| 3 | 連結語の上限 | トークン数 5 以下かつ表層 20 文字以下を既定とし、`-D` で変更可。超える連続列は連結語を作らず断片のみ |
| 4 | 連結語の品詞条件 | §3 の 11 種。`名詞-接尾-地域`(県・区)も含める案を推奨。人名接尾・助数詞・形容動詞語幹・数は対象外 |
| 5 | `SuggestItem` の words / reading | `words = { 連結語 }` の 1 語・区切りなし(`text = "新型コロナ"`)。`{新型, コロナ}` にすると `text` が空白区切りになり複数語項目と混ざる。readings は 1 要素。ID が一致するので、検索ログ由来の同じ語と統合される |
| 6 | 読みの生成 | 構成トークンの `reading`(無ければ term)をカタカナのまま連結してから、既存の `contentsReadingConverter.convert` に 1 回通す |
| 7 | 表層形の正規化 | 連結後に `toLowerCase(Locale.ROOT)`。`content_length` の 30 文字上限と bad word 判定は既存どおり |
| 8 | 品詞が取れない場合 | 連結せず従来動作(縮退) |
| 9 | 設定の置き場所 | 既存の `fess.suggest.max.analyzed.content.length` と同じ System property(`jvm.suggest.options` で渡せる)。有効フラグ(既定 on)・最大トークン数・最大文字数の 3 つ。`FessConfig` への追加は不要 |
| 10 | `_analyze` 回数 | 初版は既存 2 回に explain を 1 回足す(安全側)。3 回分への統合最適化は Y-10 側に切り出す |
