# デモ環境でのサジェスト品質評価

0001（ローカル環境）と同じ観点・クエリで、デモ環境の `GET /api/v1/suggest-words`（`field=_default&field=content&field=title`、num=15）を約110クエリ確認した。

## 評価条件・制約

- データ: fess/OpenSearch関連の技術文書（多言語）と BuzzFeed 系記事が混在し、各候補に `labels`（`fess`/`buzzfeed`）が付く。ローカル（はてなブックマーク100件）とは語彙が全く異なる。
- v1 には検索API（`/api/v1/search`）が無く、「文書に存在するのに候補が出ない」ことの裏取りはできない。0件の原因がデータ不在か処理かは区別できていない。
- 以降、0件は `record_count=0` の応答（`data` キー自体が無い）を指す。

## ローカルとの比較から言えること

- 複数語0件・断片・読み一致ノイズ・1文字語・ゴミ文字列は両環境で再現するため、データ起因ではなく生成・フィルタ処理の問題と考えられる [推測]。
- 数字は両環境で挙動が逆（ローカル0件／デモは大量のタイムスタンプ）。数字の扱いに一貫したルールが無いと見られる [推測]。
- 多言語混在（D1）は、デモのコーパス特有だが、実運用でも多言語サイトでは起こるため、言語別フィルタの対象にする。
- デモはローカルより古い版であり、差分（`ッ` が0件、`ハンバーガー` が存在する等）の一部は版差・データ差である可能性が残る。
