## 3 分サマリ

**何をするのか。** fess のサジェスト機能を提供するライブラリ `fess-suggest` を、メジャーバージョンアップ級で作り直します。10 年以上ほぼ手が入っておらず、公開 API が肥大化し、直しにくく、性能上のムダも溜まっているためです。

**ただし全面書き直しではありません。** 調査の結論は「**アーキテクチャは健全。重大度『高』の課題はゼロ**」でした。テキスト処理パイプラインやゼロダウンタイム再構築の仕組みは筋がよく、そのまま活かします。作り直すのは**公開面（API）・データの形・入れ替え手順**の 3 つです。

**やり方は「置き換えながら移行」**（Strangler Fig）。新しい実装を別パッケージに並べて置き、古い入口はそこへ委譲させ、呼び出し元を順に切り替え、最後に古い方を消します。一気に全部入れ替えることはしません。

**例外が 1 つあります。** ドキュメントの ID の作り方を変えるため、**新旧のインデックスを混ぜて使うことはできません**。ここだけは「新しい形で全件入れ直す → 検証する → 切り替える」の一本道です。

**現在の状態。** 設計は完成し、外部レビューを 4 回受けて第 8 版まで来ています。**実装はまだ 1 行も書かれていません**（設計だけがスコープでした）。

## 何がどう変わるのか（一覧）

| | 今 | これから |
| --- | --- | --- |
| **公開 API** | `Suggester` と `SuggestIndexer` の 2 クラスに約 48 個のメソッドが同居 | 用途別の **4 インタフェース・30 メソッド**に整理 |
| **拡張のしかた** | 拡張点が決まっていない。手を入れるには本体を読む必要がある | **7 つの差し替え点（SPI）** を用意。ソース追加・スコアリング変更などが載る |
| **非同期** | 独自の `Deferred` / `Promise` | **`CompletableFuture` に統一** |
| **1 語を表す型** | `SuggestItem` 1 つが入力・保存・検索結果を兼任 | **3 つに分離**（取り込みたい情報 / 保存されている状態 / 検索結果） |
| **ランキング用スコア** | 登録時に計算して保存しているが**誰も読んでいない**（死蔵） | 保存をやめる。ランキングは検索時の計算だけ |
| **書き込み** | 1 件ずつ同期 Get → まとめて書き込み | **まとめて Get**（multiGet）してから書き込み |
| **refresh** | バッチごとに同期 refresh。既定 2 件なので**100 万件で 50 万回** | バッチごとの refresh を廃止。再構築中は自動 refresh を止める |
| **ドキュメント ID** | 文字列を Base64 して 445 文字で切る → **長い語が衝突する** | **SHA-256 のハッシュ（43 文字固定）**。切り詰め自体をなくす |
| **NG ワード（bad word）** | 物理削除。**消したら戻せない** | `excluded` フラグで論理的に隠す。**登録を取り消せば復活する** |
| **シャード数** | ファイルに `1` と書かれていて外から変えられない | fess 本体の設定から渡せる |
| **再構築の切り替え** | 取り込みが失敗しても**無条件に切り替え**、直後に旧世代を物理削除 | 3 つのガードを通過したときだけ切り替え、旧世代は保持 |
