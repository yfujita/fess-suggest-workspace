## A. パッケージの分け方

まず「どこを触っていいか」を、パッケージの名前で分かるようにします。

| パッケージ | 何が入るか | fess 本体から使ってよいか |
| --- | --- | --- |
| `api` | **公開 4 インタフェース**とその DTO | **使ってよい** |
| `spi` | **差し替え点 7 インタフェース**と補助型 | 実装を差し替えるとき以外は使わない |
| `internal` | 上記の実装 | **使わない** |
| `settings` | 設定（既存パッケージを拡張） | 使ってよい |
| `entity` | `SuggestItem` / `ElevateWord`（既存を維持） | 使ってよい |

**依存の向きは `spi` → `entity` → `api` の一方向**に揃えます。`api` を読むだけで公開面が完結する状態を作るためです。
また **`api` / `spi` に OpenSearch の型を一切出しません**。今は `QueryBuilder` が公開面に漏れていて、ストレージを差し替える余地がありません。

## B. 公開する 4 つのインタフェース（合計 30 メソッド）

今は `Suggester`（18）＋ `SuggestIndexer`（30）の 48 メンバがフラットに並んでいます。これを**用途別**に配り直します。

### 1. `SuggestQueryService` — 検索する（2 メソッド）

サジェスト検索と人気語取得だけ。

```java
CompletableFuture<SuggestResult> suggest(SuggestQuery query);
CompletableFuture<SuggestResult> popularWords(PopularWordsQuery query);
```

**「詳細あり版」と「軽量版」にメソッドを分けることはしません。** 代わりに**リクエストで欲しい属性を指定**し、レスポンスが「実際にどの属性を埋めたか」を自己申告します。メソッド選択とフィールド指定の 2 系統ができると、今の「何が返るか呼び出し側から見えない」問題が形を変えて再発するためです。既定は現状互換の `text` と `tags`。

### 2. `SuggestIndexLifecycle` — インデックスの世代を管理する（12 メソッド）

作成・世代切替・破棄・統計、そして**エイリアス操作の原子的な部品**を提供します。

主なもの:

| メソッド | 役割 |
| --- | --- |
| `createNextIndex` | 次世代インデックスを作り、更新エイリアスだけを付け替える |
| `switchIndexRetainingPrevious` | **旧世代に `.prev` を付けつつ、検索エイリアスを新世代へ移す**（1 リクエストなので中間状態が生まれない） |
| `rollbackToPrevious` | 検索エイリアスを `.prev` の世代へ戻す |
| `validateNext` | **切り替える前に、新世代へ本番と同じクエリを撃って確かめる** |
| `updateRefreshInterval` | 再構築中に止めていた自動 refresh を戻す |
| `aliasState` | 3 つのエイリアスが今どこを指しているかを返す（運用・調査用） |

**「再構築を丸ごとやってくれる API」は作りません。** いつ切り替えるか・切り替えてよいかの判断は呼び出し元（fess 側）に残します。ここが提供するのは**部品**だけです。

> **失敗の扱いに一工夫あります。** エイリアス操作はタイムアウトしてもサーバ側では適用済みのことがあります。そこで「例外が出なかったこと」ではなく「**目的の状態になっていること**」を成功の定義にしました。例外が出たらエイリアス状態を読み直し、目的の状態なら成功として返します。判断できないときだけ専用の例外を投げ、呼び出し元は「成功 / 未適用 / 判定不能」の 3 分岐を書きます。

### 3. `SuggestWordAdmin` — NG ワードと優先語を管理する（7 メソッド）

`addBadWord` / `deleteBadWord` / `deleteAllBadWords` / `previewBadWordImpact` / `addElevateWord` / `deleteElevateWord` / `restoreElevateWords`。

- **`apply` 引数を全廃**します。今の 3 箇所にある `apply` は、fess からは常に `false` で呼ばれていて実質意味がありません。
- **`previewBadWordImpact` は新機能**です。「この NG ワードを登録すると何語が除外されるか」を、**変更せずに**先に見せます。
- **NG ワードの取り消しは慎重に効きます。** 判定が部分一致なので、1 つの語が複数の NG ワードに同時に該当しえます。`foo` と `bar` が登録されている状態で `foo` だけ消したとき、**まだ `bar` に該当している `foobar` は復活させません**。

### 4. `SuggestIngestService` — 取り込みと削除（9 メソッド）

`index` / `indexFromDocuments` / `indexFromSearchWord` / `indexFrom` / `deleteById` / `deleteByCondition` / `deleteAll` / `deleteByKind` / `deleteOldWords`。

`indexFrom` が**新しい供給元を載せる唯一の実行点**です。「ソースを登録しておけば勝手に動く」形は採りませんでした（実行のタイミングと入力を誰が持つのかが決まらないため）。

## C. 差し替えられる 7 つの点（SPI）

新機能は基本的にここに載ります。

| SPI | 何を差し替えられるか |
| --- | --- |
| `SuggestSource<I>` | **候補の供給元**。入力 `I` を取り込み候補の列に変換するアダプタ。同義語・関連語・トレンドなどを後から足す口 |
| `ScoringStrategy` | **加点のしかた**。用意された加点要素（頻度・boost・完全一致・ベクトル類似度など）の組み合わせ方を差し替える |
| `TextProcessor` | **テキスト処理**。言語別実装への差し替え・追加。多言語強化やタイプミス正規化の口 |
| `SuggestItemMergePolicy` | **同じ語をどう合体させるか**。頻度の足し方など |
| `BadWordPolicy` | **NG ワード判定の唯一の持ち主**。取り込み時の判定とストア問い合わせ条件の両方を同じ場所から出す |
| `AuthorizationFilter` | **権限条件の生成**。ロール未指定でも全件は見せない（デフォルト deny） |
| `SuggestStore` | **永続化の境界**。OpenSearch 実装を差し替えられるようにする |

**組み立て場所は `SuggesterBuilder` 1 箇所**に決めました。どこに登録するのか・既定実装は何か・順序はどうなるかが決まっていないと、SPI は形だけで実際には使えないためです。

## D. 「1 語」を表す型を 3 つに分ける

今は `SuggestItem` 1 つが、入力・保存・マージ・検索結果の 4 役を兼ねています。これを分けます。

| 型 | 意味 | 性質 |
| --- | --- | --- |
| `SuggestCandidate` | **こう取り込みたい**という意思 | 部分的でよい |
| `SuggestItem` | **保存されている 1 語の完全な状態** | 全部埋まっている |
| `SuggestHit` | **検索結果として返す分だけ** | 部分的でよい |

これで解ける問題が 2 つあります。

- **`userBoost` の「指定あり / なし」**。`SuggestCandidate` 側だけが「指定なし」を表現でき、**指定ありのときだけ既存値を上書き**します。通常の取り込みは常に「指定なし」なので、**管理画面で設定した boost が取り込みで消える**現象がなくなります。
- **`excluded`（NG ワードによる除外フラグ）**。`SuggestItem` だけが持ち、`SuggestCandidate` は持ちません。つまり**取り込み経路から除外フラグを立てられないことが、規約ではなく型として保証されます**。

公開する DTO は `record` ではなく **`final class` ＋ 不変コレクション**にします。`record` が不変にするのは参照だけで、配列の中身は呼び出し側から書き換えられてしまうためです。

## E. 非同期とエラーの扱い

- **公開 4 インタフェースの全メソッドが `CompletableFuture` を返します。** 独自の `Deferred` / `Promise` は廃止。同期で使いたければ `join()` します。
- **項目単位の部分失敗は例外にしません。** 結果オブジェクトの `failures` に積みます。操作全体が失敗したときだけ例外です。
- **ただし fess の全件再構築は、部分失敗を「失敗」として扱います。** ここを見落とすと、**一部が欠けたインデックスがそのまま公開されます**。
- **スレッド安全性の約束は「同時に呼んでも壊れない」まで**です。**同じ語に同時に書くと頻度の更新が失われることがあります**（後述の既知の制約 K-1）。「壊れない」と「失われない」を分けて書いています。

## F. データの形

### 5 つの不変条件

データの正しさを 5 つの条件に集約しました。**個別の不具合に個別の対処を当てるのではなく、この 5 つが成立していれば症状のほうが消える**という組み立てです。

1. **読み仮名の第 1 次元の長さ ＝ text の語数**
2. **語自身は空白を含まない**
3. **語数は上限 N 以下**
4. **読み仮名フィールドに `null` を書かない**
5. **ID は text だけから決定的に導かれ、実用上十分に衝突しにくい**

> 5 番目は当初「異なる語は必ず異なる ID になる」と書いていましたが、SHA-256 では数学的に保証できないため書き直しました。**代わりに、まとめて取得したあとで突き合わせる検査を 1 つ置きます**。これで「確率的にしか成立しない性質の破れ」も「ID 生成の実装バグ」も同じ場所で捕まえられます。

### mapping（フィールド定義）

- **`score` を削除**（誰も読んでいなかった死蔵フィールド）
- **`excluded`（boolean）を追加**（NG ワードの論理除外用）
- **未知のフィールドを拒否する設定に変更**。ただし `reading_*` という名前だけはテンプレートで許可します
- **語数に上限 N を設ける**（既定 10 / 設定可能 / 設定上限 50）
- **`text` は `keyword` のまま**。サブフィールドも normalizer も analyzer も足しません

> **語数上限は「安全装置」ではなく、意味を変える設計判断です。** 先頭 10 語が同じ別々のクエリは、同じ 1 語として集約されます。10 が妥当かどうかは**仮定にすぎない**ため、切り捨て件数と超過クエリ数を**観測項目として定義**し、あとで引き上げ判断ができるようにしています。

### ID の作り方

```
今:    text を Base64 → 445 文字で切る   → 長文が衝突する・4 文字境界外で切れる
これから: text の SHA-256 → Base64 URL-safe（パディングなし・43 文字固定）
```

**ID の材料は `text` だけに保ちます**（種別を混ぜません）。混ぜると「同じ語なら同じ ID になるので頻度が自然に集約される」という、今回残すと決めた性質が壊れるためです。種別ごとの `userBoost` 潰れは、ID ではなく**マージ規則のほう**で解きます。

### マージ規則

- **「何語あるか」の数え方を `text` の語数 1 つに統一**します。今は 3 通りの数え方が混在していて、それが読み仮名の消失を招いています。
- 書き込みは今までどおり**全置換**です。ただし不変条件 1 が成立していれば、全置換でも消えるものはありません。
- **`excluded` は既存値を保持**します（取り込みのたびに除外が解けることがない）。

### NG ワードの扱い（可逆にする）

- 物理削除をやめ、**`excluded = true` を立てて隠す**だけにします。取り消せば戻ります。
- **suggest インデックスを読むすべてのクエリ経路**に「`excluded` が `true` のものを除く」条件を必須にします。**「`excluded` が `false` のものだけ」と書くのは禁止**です（フィールドを持たない古いドキュメントが全部消えるため）。
- **NG ワードに該当する新規の語も、捨てずに `excluded = true` で保存します。** 以前は「既存の語は可逆に隠す／新しく流れてきた語は捨てる」という非対称があり、NG ワード登録中に流入した語は取り消しても復活しませんでした。
- 代償として除外語がインデックスに残るので、**物理削除は運用が明示的に選ぶ別操作**にしました（自動では走りません）。

## G. fess 本体側の変更

**5 ファイルだけです**（Java 4 ＋ 設定 1）。

| ファイル | 何をする |
| --- | --- |
| `SuggestHelper` | 新 API へ呼び替え。**fess の公開面は変えない** |
| `SuggestWordsHandler` | 同上 |
| `PopularWordHelper` | 同上。設定値の単位表記を `60` → `60m` に直す |
| `SuggestCreator` | **切替ガードを入れる**（ここが再構築の要） |
| `fess_config.properties` | シャード数・レプリカ設定のキーを追加 |
