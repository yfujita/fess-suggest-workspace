## 計画上の判断

| 論点 | 判断 |
| --- | --- |
| フェーズの骨格 | RP §4 のフェーズ 0〜6 をそのまま使う。IP §4 の拡張点は RP の前提項目（A-07 / A-03 / B-04 / A-02 / A-06）が属するフェーズに対応付ける |
| RP と IP でエラー伝搬の順序が食い違う点 | エラー伝搬の方針は設計書 v1 で最初に決める。挙動が変わる修正（X-09 / X-14 / F-03）は「フェーズ 0.5」として構造変更から切り離す。入れるかどうかはユーザー判断（Q7） |
| 設計書を作るタイミング | v1（方針）はフェーズ 0 と並行して作る。v2（構造）はフェーズ 3 の前に作り、ユーザー承認をゲートにする。v3（実装を反映した確定版）は最後に作る |
| 判断事項の既定値 | 回答が出るまでは、挙動も公開 API も変えない側を既定値にする（Q1 は「不明扱い」） |
| 採番しない項目 | 作業履歴の番号はフェーズの実施時に決める。計画書では「最大番号 + 1」のルールだけを書く |

## 結果

- 次の作業は、ユーザーに Q1〜Q11 の回答を求めること。
