## 2. ISS カバレッジの独立再検算（点検項目2の裏取り）

各軸が扱う ISS 集合を `0014` の各章から抽出し、和集合が ISS-01〜17 を網羅するかを独立に検算した。

| 軸 | 出典 | 扱う ISS |
| --- | --- | --- |
| ①可読性 | `0014` §3.1 / §3.6 | 01,02,03,05,06,13,14,16,17（9件） |
| ②変更容易性 | `0014` §3.2 / §3.6 | 01,02,03,04,05,06,09,13,15,17（10件） |
| ③品質 | `0014` §3.3 / §3.6 | 04,05,10,11,12,14,15（7件） |
| ④性能 | `0014` §3.4 / §3.6 | 07,08,09,10,16（5件） |
| ⑤新機能 | `0014` §3.5 / §3.6 | 11,12（必達）＋ISS外機会 |

- **和集合 = {01,02,03,04,05,06,07,08,09,10,11,12,13,14,15,16,17}＝全17件**。漏れなし。
- **重複の扱い**: 複数軸に現れる ISS（例: ISS-05 は可読性/変更容易性/品質、ISS-14 は可読性/品質）は「主担当 vs 補助」の役割分担が中間成果物で明記済み（`0006` §2.6/§2.7、`0009` §6.2 が `0011` に新機能展開を委譲 等）。同一論点の再掲ではなく観点分担のため、MECE の「相互排他」を観点レベルで担保。
- **TBD**: TBD-01（OpenSearch/Lucene 数値バージョン未解決）は影響する全打ち手（MIG-15/21/24、MIG-02 案A 等）で [要確認] 明示。TBD-02 はクローズ、TBD-03 は機構上の可能性を確定・定量影響のみ残、TBD-04/05 は [推測] として §5.1 に整理。**「未確定を断定しない」方針が一貫**。

→ 点検項目2の合格を独立検算で裏付け。

## 3. 検出した軽微所見（結論に影響しない）

いずれも**修正不要レベル**と判断する。理由を添えて記録する（修正は行わない）。

### 所見1: MIG-23 の依存層配置（`0013` §6.2 / `0014` §4.5）
- 内容: MIG-23（多言語強化）は `H:MIG-12` のみをハード依存に持つ。MIG-12 は層0のため、最小到達層では MIG-23 は**層1**に置けるが、`0013` §6.2（278行）・`0014` §4.5（366行）では**層2**に列挙されている。
- 影響: なし。層分割は循環検出のための「すべての辺が下位層→上位層へ向くか」を見る目的であり、MIG-23(層2)←MIG-12(層0)は前方辺で循環を生まない。DAG・循環なしの結論は不変。配置はやや保守的（高め）なだけ。
- 対応: 修正不要。循環チェックの妥当性に影響しないため指摘のみ記録。

### 所見2: 付録「参照ドキュメント一覧」が中間プロセス文書を含まない（`0014` 付録 423-437行）
- 内容: 付録の参照一覧は `0002`,`0003`,`0005`,`0006`,`0008`〜`0013` を列挙するが、`0004-revise-step3-zero-base.md`（ステップ3のゼロベース方針への改訂記録）と `0007-add-step3-7-google-comparison.md`（3-7 追加の決定記録）を含まない。
- 影響: なし。`0004`/`0007` は**成果物（設計・課題の内容ソース）ではなくプロセス／改訂の決定記録**であり、`0014` は「判断根拠として統合・集約した成果物」を列挙する趣旨（439行）。内容トレーサビリティは保たれている。
- 対応: 修正不要。意図に沿った取捨選択と判断。本書でその位置づけを明記することで補完する。

> 上記2件以外に、事実/提案の取り違え・カバレッジ漏れ・依存矛盾・影響区分の欠落は検出されなかった。

## 5. 判断の根拠（自己検証の進め方）

- **点検項目1（5目的カバー）**: 提案側の「カバレッジを主張する箇所」(`0014` §3.6) と要件側 (`0000` 目的) を双方向で突き合わせ、各目的に主担当章・設計判断・ISS・MIG が紐づくことを確認した。主張の有無だけでなく**対応先の実在**（中間成果物の節）まで辿った。
- **点検項目2（MECE）**: `0014` の集約表をそのまま信用せず、各軸が扱う ISS 集合を抽出して**和集合を独立に再計算**（§2）。さらに各中間成果物が自前の MECE 点検節を持つことを grep で確認し、二重に裏取りした。
- **点検項目3（依存無矛盾）**: `0013` §6 のハード依存層分割と循環なし結論を確認し、`0014` §4.5 がそれを正しく引き継いでいるか照合。層配置の保守性（所見1）も検出したが、循環検出の正当性は不変と判断。
- **点検項目4（事実/提案区別）**: 凡例の定義と全章での運用、特に As-Is に [事実]＋出典、To-Be/優先度に [提案]、TBD 依存に [要確認] が貫かれているかを確認。
- **点検項目5（影響区別）**: 各軸表の「影響範囲」列、MIG カタログの「対象／スキーマ・API」列、§4.1 後方互換3軸、§5.3 連携互換確認で fess-suggest と fess 本体の区別が体系的に保たれていることを確認。

## 6. 残課題・要確認事項（本タスクの範囲外として引き継ぐ）

本書は文書間整合の自己検証であり、以下は提案の性質上クローズできず後続に委ねる（`0014` §5 と重複しない、検証観点での残件）。

- **定量検証の不在**: bad word 誤削除の実データ影響、`scripted_upsert` vs multiGet のスループット差、score 案A/案B の QPS 別レイテンシ、セマンティックのレイテンシ等は実測（負荷試験・A/B）が必要でスコープ外（`0014` §5.3）。自己検証は「論理整合・トレーサビリティ」までを担保し、「提案の効果の実証」は担保しない。
- **TBD-01 への構造的依存**: 性能・新機能の打ち手の相当数が OpenSearch/Lucene 数値バージョン（`fess-parent:15.7.0`、ワークスペース外）に依存。`fess-parent` POM 確認が前提（`0014` §5.1）。本検証では「[要確認] 表記の一貫性」のみ確認可能で、バージョン自体は未解決のまま。
- **fess 本体連携部のテスト手薄**: MIG-06/08/09/10/18/22 は fess 本体同時改修・テスト補強が前提（`0014` §4.1 ③／§5.3）。移行実施時の検証計画は後続タスクの領分。
