# 0004: 作業プランのステップ3をゼロベース再実装版へ改訂

## 1. 概要

本ドキュメントは、作業プラン `0001-work-plan.md` の**ステップ3を「ゼロベースでの再実装によるあるべき姿の設計」へ書き換えた**作業の履歴である。

- 対象タスク: `20260622_improvement_proposal`（fess-suggest 抜本的改善提案）
- 改訂対象ファイル: `agent_docs/tasks/20260622_improvement_proposal/0001-work-plan.md`
- 改訂の主対象: ステップ3節（旧 `### ステップ3: 検討軸ごとの「あるべき姿」と改善案の検討（A〜E に分割）` 配下の 3-A〜3-E）
- 付随改訂: 概要のフロー記述、ステップ4の導入文（ステップ3の趣旨変更との整合のための最小修正）

## 2. なぜ変えたか（背景・意図）

要件定義（`0000-requirements-definition.md`）に「**既存モジュールの構成を維持する必要はなくゼロベースで検討を行い、あるべき姿を目指す**」とある。
一方、改訂前のステップ3は「現状課題 → あるべき姿 → 改善案（漸進的改善 + 再設計）→ トレードオフ」という構成で、**既存モジュール構成を前提とした漸進的リファクタリング寄り**の組み立てだった。

そこで、ステップ3の軸足を以下のように移した。

- 「既存の課題を一つずつ直す」発想 → 「もしゼロから作り直すなら fess-suggest はどうあるべきか」という**理想形（To-Be アーキテクチャ）を主軸に設計する**発想。
- 既存課題（ISS/TBD）は「直す対象」ではなく、**「ゼロベース設計が回避・解消すべきアンチパターンの実例」**として参照する位置づけに変更。
- 現行プランの良さ（両論併記による意思決定材料）は維持し、各設計判断に**「ゼロベース To-Be 案（主）＋既存維持の漸進案（従・対比）」を併記**。ただし**移行戦略・差分はステップ4へ役割分担**。

## 3. 何を・どう変えたか（変更前後の要点）

### 3.1 ステップ3の構造変更

| 観点 | 改訂前 | 改訂後 |
| --- | --- | --- |
| 構成軸 | 5検討軸ごとの並列ステップ 3-A〜3-E（各軸で現状課題→あるべき姿→改善案） | **ステップ3-1「To-Be アーキテクチャ全体像の設計」を主軸**に置き、3-2〜3-6 で「あるべき姿が5目的をどう満たすか」を照合する構成 |
| 起点の発想 | 課題起点の漸進的改善（再設計案は「望ましい」オプション） | **ゼロベース理想形（To-Be）起点**。課題はアンチパターンの実例として参照 |
| 漸進案の扱い | 漸進案と再設計案を「両方提示できると望ましい」 | To-Be 案を主、漸進案を**対比用に併記**（移行はステップ4へ委譲） |
| 既存資産 | 明示なし | **踏襲・再利用する資産を明示**（充実したテスト群: main 64ファイル/11,591行 vs test 77ファイル/15,194行、良好なテキスト処理パイプライン約1,369行） |
| 完了条件 | 「軸ごとに改善案候補が複数」「MECE 点検」 | 「各設計判断に解消される ISS/TBD が紐づく」「5目的の To-Be での実現を漏れなくカバー」「全 ISS(01〜17) を参照」「再利用資産の明示」 |

### 3.2 ステップ3-1（新設・主軸）に盛り込んだ設計レイヤ／論点

ゼロベースで設計するレイヤを、対応する現行課題（解消対象）とともに明示した。

- コンポーネント構造（ISS-13 ファサード肥大: `Suggester` 507行/public18・`SuggestIndexer` 547行/public28 を回避する用途別 API 境界）
- データソース抽象（ISS-01 デッドパス。新規ソースを最初から追加可能にする拡張点）
- テキスト処理パイプライン（良好な現行資産を踏襲する位置づけ）
- インデックス設計（ISS-07/TBD-05 単一シャード、ISS-14/16 事前計算 score の要否を含むスキーマ）
- 書き込み／集約モデル（ISS-10 Get-then-update 1件ずつ同期、ISS-05 マージ規則二重実装の排除）
- 同期／非同期モデル（ISS-09 不均一境界。独自 Deferred/Promise の踏襲 or 置換方針）
- スコアリング機構（ISS-14 死蔵 score を整理しランキング源を一系統化、ISS-04 bad word 誤削除を排した語管理）
- 権限・フィルタ（ISS-06 二重担保の解消）

各論点に (a) 設計意図、(b) 解消される ISS/TBD、(c) 漸進案との対比 を添えることを完了条件にした。

### 3.3 付随修正（最小限）

- **概要**: フロー記述を「現状の課題 → あるべき姿 → 改善案 → 優先度・ロードマップ」から「As-Is 把握 → ゼロベース To-Be 設計 → 移行戦略・優先度・ロードマップ」へ変更。
- **ステップ4**: 見出しを「改善案の優先度付けとロードマップ化」→「**既存からの移行戦略・優先度付けとロードマップ化**」に変更し、**To-Be↔As-Is 差分整理と移行戦略（一括リプレース vs 段階的移行）**を明示的にステップ4の領分とした。ステップ3で併記する漸進案を移行経路としてここで活用する役割分担を記述。
- ステップ番号・他ステップ（1,2,5,6）の見出し・前提・スコープ・検証方針・リスク節は維持。

## 4. 5目的カバレッジの担保方法

要件の5目的が漏れなくカバーされることを、以下の二重の仕組みで担保した。

1. **ステップ3-2〜3-6 を5目的に1対1対応**させた（3-2 可読性 / 3-3 変更容易性 / 3-4 品質 / 3-5 性能 / 3-6 新機能）。各サブステップの完了条件に、対応する ISS 群が「To-Be のどの設計判断で解消されるか」の対応を示すことを必須化。
2. **ステップ3全体の完了条件**に「5目的すべての To-Be での実現を漏れなくカバー」「全 ISS(01〜17) をいずれかで参照（MECE 点検）」を明記。

ISS の各サブステップへの割り当て（`0002`/`0003` のカバレッジ表に準拠）:

- 可読性(3-2): ISS-01,02,03,05,06,13,14,16,17
- 変更容易性(3-3): ISS-01,02,03,04,05,06,09,13,15,17
- 品質(3-4): ISS-04,05,10,11,12,14,15
- 性能(3-5): ISS-07,08,09,10,16
- 新機能(3-6): ISS-11,12

新機能(3-6) は「後付けでなく設計の最初から内包する」方針を明記し、データソース抽象・スコアリング機構・インデックス設計（3-1）の拡張点に載せる形で設計することとした。
