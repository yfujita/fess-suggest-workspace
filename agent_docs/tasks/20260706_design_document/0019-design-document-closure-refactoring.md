## 2. 作業 1: 閉包の監査

### 2.1 監査方法

`0001`〜`0003`（＋ `0004`）の本文に出現する識別子を機械的に列挙し、`0000`（＋ `0004`・恒久文書 `improvement-proposal.md`）内で解決できるかを突き合わせた。

```
grep -oE '\b[A-Z]{1,4}-?[0-9]{1,2}[a-z]?\b' <各文書>   # 番号の列挙
grep -nE '\.\./[0-9]'                                   # 相対リンクの列挙
```

判定は「その番号が `0000` / `0004` / 恒久文書のいずれかで**表の先頭セルとして定義されている**か」で行った。

### 2.3 副産物として検出した番号衝突（3 系統 → 2 組）

監査の過程で、**同じ文字を別の意味で使っている系統**が見つかった。設計内容の誤りではないが、閉じた集合として読むときの誤読源になる。

| 文字 | 系統 A | 系統 B | 処置 |
| --- | --- | --- | --- |
| `T` | **T-1〜T-5**: 行番号・所在の訂正（`0000` §3.4 の台帳） | **T-1〜T-23 / T-11b / T-14b**: `0002` §7.2 の回帰テスト番号 ／ **T-S・T-R・T-F 系**: `0003` §11 | **表記は変えず**、`0000` §3.4 に対応表を追加 |
| `G` | **G-1〜G-5**: `0004` §3 の局所番号 | **G1〜G3**: `0003` §4.2 の切替可否ガード（MO-3） | 同上 |

**表記を変えなかった理由**: 各文書内では一意であり、番号を振り直すと版間の追跡可能性（改訂履歴・外部レビュー指摘との対応）が壊れるため。**読み分けの規則を台帳に書くほうが安全である。**

> なお、当初 `F1`〜`F4` を第 3 の衝突として検出したが、**実体は `T-F1`〜`T-F4`（`0003` §11.3 の fess 側テスト番号）であり、正規表現が接頭辞 `T-` を落としていたことによる誤検出**だった。台帳には注記としてのみ残した。

### 5.3 意図した 2 つの例外（`0000` §3.5 の規律に明記）

| 例外 | 理由 |
| --- | --- |
| **`0000` 全体** | 本書は**索引**であり、「どの番号がどこで確定したか」を示すこと自体が役割である。§3.4 の「定義（原典）」欄・§5 の「原典」欄を落とすと索引として機能しない。**表記のみテキスト化し、参照は残した** |
| **`0004` の §1.1 / §2 の「対象」欄 / §4** | 訂正台帳にとって**対象文書の同定は本文そのもの**であり、リンクではなく識別子である。E-07 / E-13 / E-14 / E-19 / E-20 / E-21 / E-22 / E-25 / E-08 / E-09 / E-10 / E-17 は作業記録の誤りを訂正する行であるため、対象を落とすと台帳の意味が失われる |

**この 2 つの例外は `0000` §3.5 に規律 6 として明文化した。** 暗黙の逸脱を残さないためである。
