# 改善提案書レビュー指摘の反映（第4版）

## 概要

`docs/improvement-proposal.md`（第3版）に対するレビュー指摘4件を検証のうえ全件反映し、**第4版**とした。
指摘はいずれも妥当と判断し、修正を却下したものはない。

## 反映内容

### 1. §2.2 見出しの番号更新漏れ（再発）

**指摘**: 見出しが「課題インベントリ（ISS-01〜18）」のまま表には ISS-19 が入っている。第2版で「〜17→〜18」を直した直後に 19 を追加して同じ漏れが再発。番号を見出しに含める運用自体が温床。

**対応**: 個別修正ではなく**構造的に止める**方針を採った。

- 見出しを「**課題インベントリ（ISS）**」と番号なしに変更。
- §2.2 冒頭に記述ルールを明記（番号範囲の記載は「追加の出自を説明する箇所」に限定し、一覧の同一性は表そのもので担保する）。
- 同種の漏れを横断チェックし、以下も番号なし表現へ統一:
  - §3.6 末尾「全 ISS（01〜19）が…」→「**§2.2 の全 ISS** が…」
  - §6 完了条件表「全 ISS(01〜18) を MECE にカバー」→「**§2.2 の全 ISS** を MECE にカバー」（こちらは 18 のままで二重に古かった）
- §2.2 冒頭の出自説明も「ISS-18 は本書レビューで追加」→「**ISS-18（本書レビュー）・ISS-19（第3版）**は本書固有の追加項目」に補正。
- **追補（レビュー第2巡）**: 同じパターンの残件として **§4.2 見出し「移行単位カタログ（MIG-01〜25）」→「移行単位カタログ（MIG）」** を修正。あわせて §2.2 の記述ルールを「**追加され得る採番体系（ISS / MIG）の見出し全体に適用する**」と一般化した。※ §2.3 の TBD-01〜05 は全件クローズ済みで以後追加されない**閉じた集合**のため、範囲表記のまま据え置くことを明記（漏れではなく意図的な据え置き）。
- あわせて指摘された §1.4 クイックウィンの表記ゆれを修正: 「MIG-16（バルク件数）」→「**MIG-16（バルク件数＋refresh 分離）**」（§4.3 クイックウィン表・§4.4 Phase 3 と表記統一）。

### 2. `apply` パラメータの最終的な扱いが未定義

**指摘**: bad word は「③`excluded` 既定、①は明示オプションとしても残さない」と確定したが、`addBadWord(badWord, apply)` の `apply` 引数の API 上の運命が未記述。MIG-03（既定オフ）→ MIG-13（`excluded` 既定）と段階が分かれるため、各段階での `apply=true` の挙動定義が必要。提案書の欠陥ではなく設計書タスクへの申し送り事項。

**対応**: 指摘のとおり**申し送り事項**として記載（本書では決定しない）。

- §5.2 の bad word 行に申し送りブロックを追加。選択肢を明示:
  - (a) `@Deprecated` にして無視（no-op 化）
  - (b) 意味を「論理除外を既存文書に即時適用するか」に差し替え（MIG-13 の `excluded` 一括付与トリガ）
  - (c) 新 API（`SuggestWordAdmin`）ではシグネチャから削除し、旧ファサードのみ (a) で維持
  - いずれの案でも fess は `apply` を明示指定しているため**実挙動は不変**（§2.1）である旨も併記。
- §4.2 の **MIG-03** 行（本段階では既定オフ＝`true` でも物理削除しない／`@Deprecated` 化するか）と **MIG-13** 行（最終形の確定）にそれぞれ §5.2 への参照を追加し、段階ごとに定義が要ることを明示。

### 3. refresh 廃止の安全性根拠（マージ正しさへの非依存）

**指摘**: MIG-16② のトレードオフが「逐次可視性の喪失」だけに触れており、より重要な「書き込み経路（Get-then-update）が refresh に依存しないこと」が書かれていない。決定的 ID の `prepareGet` は realtime get（translog 読み）なので refresh 不要で、同一取り込み内で同じ語が連続バッチに現れても頻度集約は壊れない。

**コード追検証（[事実] として反映）**:

- `SuggestIndexWriter.java:55`: `client.prepareGet().setIndex(index).setId(item.getId()).get(...)` — **ID 指定 GET**（決定的 ID＝KEEP-03）。`setRealtime(false)` の指定はなく、OpenSearch の GET は既定 realtime（translog 読み）。
- `ContentIndexingOperations.java:345`: `client.admin().indices().prepareRefresh(index)...` が `docPerReq` 件ごとに同期発行されている（第3版の記述どおり）。

**対応**:

- §4.2 MIG-16 に「**安全性の根拠（第4版で追加・最重要）**」ブロックを新設し、realtime get のためマージ正しさが refresh に非依存であること、トレードオフは可視性のみであることを明記。
- 設計書への申し送りとして3点を追加:
  1. 「realtime get のためマージ正しさは refresh に非依存」を設計書に明記する
  2. **refresh 廃止後に「同一語が連続バッチに現れるケースで頻度が正しく集約される」回帰テスト**を含める（MIG-15 第1段の multiGet 化後も同様。multiGet も既定 realtime）
  3. **再構築時は投入中 `refresh_interval=-1` → 完了後に既定へ復帰**という定石を設計オプションとして検討する（KEEP-02 の並行構築と相性が良い）
- §3.4 の ISS-08 行にも要約（「廃止しても集約は壊れない [事実]」）を追記し、§4.2 へ参照。
- §5.3 の「refresh 分離による可視性低下の許容」に「**影響は可視性のみ。頻度マージの正しさは非依存**」を補足。

### 4. ISS-19「暫定修正を先行適用済み」と本書の憲章の緊張

**指摘**: 冒頭で「本書は提案＝意思決定材料であり実装指示ではない」と宣言している文書が実施済みの修正を含むのは原則との不整合。実害はないが「文書修正のみ・コード無変更のため例外的に先行適用」の一言があると規律が保たれる。

**対応**: 例外である旨を明記（2箇所）。

- §2.2 ISS-19 行: 「**本書の憲章に対する例外**であり、**文書修正のみ・プロダクションコード無変更・誤誘導の即時停止が目的のため例外的に先行適用した**もの」を追記。
- §3.1 ISS-19 行: 「文書修正のみ・コード無変更のため、提案書としての原則に対する例外として先行適用」を追記。
