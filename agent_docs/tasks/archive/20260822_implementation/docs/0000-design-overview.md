### 3.2 各設計書の冒頭に置く宣言フォーマット

**0001 / 0002 / 0003 の執筆者は、以下をそのまま冒頭に貼って埋めること。** 申し送りがどこに着地したかを機械的に検査するための装置である（要件定義の運用ルール (1)）。

```markdown
# 000N [文書名]

> 対象: fess-suggest 改善設計 ／ 実施日: YYYY-MM-DD
> 凡例: `0000-design-overview.md` §3.1 に同じ
>
> **対象 MIG**: MIG-XX（完全設計）, MIG-YY（完全設計）, MIG-ZZ（拡張点の形状のみ）
> **消化する申し送り**: 〈申し送り名〉→ §N.M ／ 〈申し送り名〉→ §N.M
> **依存する [確定] 番号**: `0000` §5 の C-XX, C-YY ／ `0000` §5.1 の P6, P11, U4
> **消化する [確認] 事項**: F-01, F-04（`0000` §5.2）
```

**「依存する [確定] 番号」欄の書き方**（曖昧さを残すと後述の着地確認が形式検査として機能しないため規則を固定する）:

- **C 番号（§5）・P 番号・U 番号（§5.1）のいずれも同じ欄に書く。** 前提と [確定] を別欄に分けない。P/U は §5.1 で本書に取り込まれているため、C 番号と同格に扱う。
- **書くのは本書 §5 / §5.1 / §5.2 / §5.3 に載っている番号だけ**とする。原典（`0001-unresolved-items-resolution` §2.X・作業プラン §1.1 / §6.1・`0004-new-findings` §3・`0009-reading-field-policy` §5）は本書から引けるので、設計書側には原典の文書名・節番号を書かない。**設計書本文から作業記録への相対リンクを張らない**（§3.5）。
- **P/U に C 番号を振り直さない。C-15 以降を新設しない。** C 番号は `0001` §2 の 14 件に固定する（§5 冒頭）。
- **4 欄すべてを埋める。** 該当が無い欄は「該当なし」と理由を書く（空欄にしない）。ステップ 7 で `0003` の「消化する [確認] 事項」欄の欠落を補った。
