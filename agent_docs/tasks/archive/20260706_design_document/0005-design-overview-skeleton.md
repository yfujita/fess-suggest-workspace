## 2. 変更内容と判断理由

### 2.1 MIG 対応表（§4）— MIG-15 の 2 行分割と ID-01 の独立行

- **MIG-01〜25 の全 25 件を表に載せた**。表の行数は 27 行で、内訳は **MIG 行 26 行**（25 件のうち **MIG-15 を「第 1 段」「第 2 段」の 2 行に分割**したため 25 + 1）＋ MIG 外の **ID-01** 1 行。
- **MIG-15 を分割した理由**: `0001-unresolved-items-resolution.md` §2.3 [確定] により、第 1 段（multiGet）は**完全設計**、第 2 段（`scripted_upsert`）は**拡張点のみ**と深さが異なる。1 行にまとめると「深さ」欄が両論併記になり、V1 の「未割り当て 0 件」判定が曖昧になる。
- **ID-01 を独立行にした理由**: P11 で今回スコープに追加された決定的 ID の再設計は MIG 番号を持たない。作業プラン §3 ステップ 2 が「カバレッジ表が MIG 番号だけで構成されているとこの項目が表から漏れる」と明示的に警告している。MIG-02 に相乗りする旨を区分欄・担当節欄の両方に書いた。
- **節番号は暫定表記とした**。`§x-y` は作業プランのステップ番号であり、実体の節番号ではない。§4.1 にその旨を明記し、ステップ 7 のチェックリスト（§8.1 の 7-1）に置換作業を登録した。**現時点で実体を持たない節番号を書くと、後から偽リンクが残る**ため。
- 深さの区分は作業プラン §1.2 と `0001-unresolved-items-resolution.md` §2.5 に従った（Phase 1a / 1b ＋ 例外の 13/16/17 が完全設計、14・15 第 2 段・18〜24 が拡張点、25 が設計不要）。

### 2.2 [確定] スナップショット（§5）— 結論のみ・根拠は非転記

- `0001-unresolved-items-resolution.md` §2.1〜§2.14 の **14 件を C-01〜C-14 として結論だけ転記**した。追検証の経緯・コード根拠は同書にのみ置き、本書は「原典」欄のリンクに留めた（V6）。
- `C-XX` の通し番号を振ったのは、**各設計書の冒頭宣言（§3.2）で「依存する [確定] 番号」を機械的に書けるようにする**ため。原典の節番号（§2.X）を直接書かせると、参照先が本書か `0001` かが読み手に伝わりにくい。両方を併記する形にした。
- §5.1 に、`0001` の後で作業プラン側が確定させた **P5 / P6 / P9 / P11 / P12 / P13 / U3 / U4** を別表で追加した。`0001` §2 だけを見ても ID 再設計や `apply` の扱いが出てこないため、スナップショットとして不完全になる。

### 2.4 MIG-25（§7）— 設計不要である旨と実装時の作業内容

P8 [確定] のとおり、MIG-25 は 0001 / 0002 / 0003 のどこにも節を持たず、本書 §7 を唯一の着地先とした。作業内容は 25-a（README のバージョン単一ソース化）・25-b（`CLAUDE.md` の非同期サンプルを `CompletableFuture` ベースへ）の 2 件で、各々に現状 [事実]・完了条件・依存を付した。**25-b は MIG-08 完了後**という依存を明記した（提案書 §4.2 の `S:MIG-08` と一致）。

### 2.5 凡例と宣言フォーマット（§3）

- 凡例は提案書・`0001`・`0004` と**同一のものを踏襲**した（新しい流儀を持ち込まない）。ファイルパスの短縮表記ルールも `0004` §1 に合わせた。
- §3.2 の宣言フォーマットは、**0001/0002/0003 の執筆者がコピーして埋められる Markdown ブロック**として書いた。要件定義の運用ルール (1)（申し送りの着地を機械的に検査する）を満たすため、「対象 MIG / 消化する申し送り / 依存する [確定] 番号 / 消化する [確認] 事項」の 4 項目を必須とした。`0004` の F 番号を消化対象として書けるようにしたのは、ステップ 1 の成果が設計書に着地したことを追跡するため。
  - 当初は「依存する [確定] 番号（C）」と「依存する前提（P）」を別欄にしていたが、**レビュー反映（`0006`）で 1 欄に統合した**。§5.1 で P/U を本書に取り込んだ結果「P11 はどちらの欄に書くのか」が読み取れず、着地確認が形式検査として機能しなくなるため（`0006` §2.2）。

## 4. スコープ外（本ステップで**やっていない**こと）

誤解を防ぐため明記する。

- **0001 / 0002 / 0003 の内容を先取りしていない。** 対応表は「どこに書くか」だけを決めており、設計の実体（シグネチャ・mapping・手順）は一切書いていない。

- **過去タスクの文書を書き換えていない**（P9）。`0005-schema-draft.md`・`improvement-proposal.md`・作業プラン・`0004` のいずれも無変更。誤りは §6 の訂正一覧で上書きする形をとった。
- **提案書に新規 ISS を起票していない**（P9）。
- **プロダクションコードを変更していない**（P10）。README / `CLAUDE.md` は §7 に作業内容を記載しただけで、実装は後続タスク。
- **ステップ 4（`reading_*` 方針）の判断を先取りしていない。** E-02 では「推奨は案 B 系」という作業プランの記載に触れているが、**確定はステップ 4** である旨を明記した。
